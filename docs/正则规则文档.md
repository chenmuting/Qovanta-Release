# 正则清理规则文档

---

## 一、功能概述

「正则清理」用于对**提取规则产生的提取结果**做二次处理。接口响应经过提取规则（JSON 路径或 HTML XPath 子集，由规则的解析格式 `source` 决定）得到原始提取值后，正则清理规则会按配置对这些值执行正则替换，常见用途包括：

| 场景 | 示例 |
|------|------|
| 去除 HTML 标签 | `<p>hello</p>` → `hello` |
| 去除首尾空白 | `"  token  "` → `"token"` |
| 只保留数字 | `No.1024-x` → `1024` |
| 截取分组片段 | `Bearer abc123` → `abc123` |
| 去除转义/引号 | `"value"` → `value` |
| 统一格式 | 日期 `2026-09-09` → `2026/09/09`、压缩连续空白 |

处理链路：

```text
发送请求
  → 响应体
  → 提取规则（ExtractionRule，按 source 分发 JSON 路径或 HTML XPath 提取）
  → 正则清理规则（RegexCleanRule，本卡片）   ← 二次处理环节
  → 提取结果展示（响应卡片提取结果面板 / 首页卡片提取结果）
  → 链式请求变量绑定、输出映射（清理后的值参与后续步骤）
```

**重要**：正则清理只作用于**提取结果**，不会修改原始响应体，也不会影响请求的发送内容。

---

## 二、规则字段说明

在接口编辑页「正则清理」卡片中，每条规则包含 3 个输入项，对应领域模型 `RegexCleanRule` 的字段：

| 字段 | 模型字段 | 必填 | 说明 |
|------|----------|------|------|
| 作用规则名 | `targetName` | 否 | 指定该清理规则只作用于哪一条提取规则的结果，填写提取规则的「规则名称」。**留空表示对该接口的全部提取结果生效**。 |
| 正则表达式 | `pattern` | 是 | 用于匹配提取值中待处理内容的正则表达式（JavaScript 方言）。留空则该规则不生效。 |
| 替换为 | `replacement` | 否 | 匹配内容的替换文本。**留空表示直接删除所有匹配内容**。支持 `$1`~`$9`、`$&` 等特殊序列（见第五节）。 |

另有两个系统字段不在卡片中展示：`id`（规则唯一标识）与 `sortOrder`（执行顺序，等于卡片列表顺序，保存时按下标重建）。

### 2.1 作用范围（targetName）匹配规则

- `targetName` 为空：对所有提取规则的**每一个成功提取值**生效（含数组提取的每个元素）。
- `targetName` 非空：必须与某条提取规则的「规则名称」**完全一致**（区分大小写，全等比较）才生效；名称对不上时该清理规则不会被执行，也不会报错。
- 一个提取结果可能同时命中「留空的全局规则」和「指名规则」，两类规则会合并后按列表顺序一起执行。

### 2.2 执行顺序

- 同一提取结果命中多条清理规则时，按**卡片中的列表顺序从上到下**依次串行执行，前一条的输出作为后一条的输入。
- 例如：规则 1「去除所有空白」、规则 2「数字后补单位」，最终结果是两步处理叠加后的值。

## 三、执行语义

以下语义与实现一一对应，编写规则前请先确认：

| 语义 | 说明 |
|------|------|
| **全局替换** | 每条规则默认执行全局替换（实现固定附加 `g` 标志），替换提取值中**所有**匹配片段，而非仅第一处。无需手动填写 `g`。 |
| **大小写敏感** | 固定使用 `g` 标志，默认区分大小写。请使用字符类实现忽略大小写（见 4.9）。 |
| **无匹配原样返回** | 表达式合法但没有匹配到内容时，提取值保持不变。 |
| **空表达式跳过** | `pattern` 为空的规则直接跳过，不参与执行。 |
| **仅处理成功提取** | 提取失败（未找到 / 类型不匹配）的结果不进入清理流程。 |
| **数组结果逐项处理** | 提取目标为数组（`[]`、`[].key` 等）时，数组内每个元素分别应用同组清理规则。 |
| **非法表达式跳过** | 运行时构造 `RegExp` 失败的规则自动跳过并记录 warn 日志，不中断请求、不影响其他规则，提取值按未清理返回（见第六节）。 |
| **整体匹配边界** | 仅附加 `g` 标志，未启用 `m`（多行）与 `s`（dotAll）标志：`^`/`$` 只匹配提取值的整体开头/结尾，不匹配每一行的行首/行尾；`.` 不匹配换行符。多行提取值时注意此差异。 |
| **换行兼容** | 模式中的 `\n`、`\t`、`\r`（字符类外）同时匹配真实控制字符与字面转义文本，如换行或两个字符 `\\n`。替换文本中的同类转义会输出真实控制字符。 |

## 四、正则语法参考

正则清理使用 ArkTS/JavaScript 正则方言。以下每张表均给出「何时使用」与示例，帮助明确各语法元素的使用场景。

### 4.1 字符与转义

| 语法 | 含义 | 何时使用 | 示例 |
|------|------|----------|------|
| `abc` | 普通字符按字面匹配 | 匹配固定文案、固定前缀/分隔符 | `Bearer` 匹配 `Bearer abc` 中的 `Bearer` |
| `.` | 任意单个字符（不含换行） | 占位一个任意字符 | `a.c` 匹配 `abc`、`a1c` |
| `\d` / `\D` | 数字 / 非数字 | 提取或删除数字片段 | `\d+` 匹配 `1024`；`\D+` 删除所有非数字 |
| `\w` / `\W` | 字母、数字、下划线 / 其余字符 | 匹配单词、标识符 | `\w+` 匹配 `user_name` |
| `\s` / `\S` | 空白（空格、制表、换行等）/ 非空白 | 去除空白、压缩空白 | `\s+` 匹配连续空白 |
| `\\` `\.` `\*` `\(` … | 转义特殊字符，匹配其字面值 | 匹配正则符号本身（点、星、括号等） | `\.` 匹配小数点；`\(` 匹配左括号 |
| `\n` `\t` `\r` | 换行、制表符、回车 | 处理多行或转义文本 | `\n` 可匹配真实换行，也可匹配字面文本 `\\n` |

### 4.2 字符类

| 语法 | 含义 | 何时使用 | 示例 |
|------|------|----------|------|
| `[abc]` | a、b、c 中任意一个 | 少量候选字符任选其一 | `[Tt]rue` 兼容大小写 |
| `[^abc]` | 除 a、b、c 外的任意字符 | 排除/删除不想要的内容 | `[^\d]+` 删除非数字 |
| `[a-z]` `[0-9]` | 范围匹配 | 匹配某类连续字符 | `[a-f0-9]+` 匹配十六进制串 |
| `[\u4e00-\u9fa5]` | 中文汉字范围 | 只保留/只匹配中文 | 见第八节「只保留中文字符」 |

注意：字符类内大部分特殊字符（`.`、`*`、`|` 等）自动按字面处理，无需再转义；`^` 写在首位才是"排除"语义。

### 4.3 量词

| 语法 | 含义 | 何时使用 | 示例 |
|------|------|----------|------|
| `*` | 0 次或多次 | 可有可无的内容 | `\d*` 匹配 ``、`123` |
| `+` | 1 次或多次 | 至少出现一次 | `\d+` 匹配 `123` |
| `?` | 0 次或 1 次 | 可选内容 | `https?` 兼容 `http`/`https` |
| `{n}` / `{n,}` / `{n,m}` | 恰好 n 次 / 至少 n 次 / n~m 次 | 固定长度片段（日期、编号） | `\d{4}-\d{2}-\d{2}` 匹配 `2026-09-09` |
| 量词后加 `?`（`.*?` `+?` `??` `{n,m}?`） | 非贪婪，尽量少匹配 | 截取第一段、避免吞噬后续内容 | `^.*?(\d+)` 取第一段数字 |

注意：`{n,m}` 中的逗号后**不能有空格**，`{2, 5}` 非法，应写 `{2,5}`。

### 4.4 分组与引用

| 语法 | 含义 | 何时使用 | 示例 |
|------|------|----------|------|
| `(...)` | 捕获分组，替换时用 `$1` 按出现顺序引用 | 保留片段、重排内容 | `(\d{4})-(\d{2})` 替换 `$1/$2` |
| `(?:...)` | 非捕获分组，不占用 `$n` 编号 | 仅归组控制作用范围，不打算引用 | `(?:ab)+` 匹配 `abab` |
| `(?<name>...)` | 命名分组，便于阅读；替换时**仍用 `$n` 按序号引用** | 复杂表达式提升可读性 | `(?<year>\d{4})` 替换仍写 `$1` |
| `\1` `\2` | 反向引用，匹配与第 n 个分组相同的内容 | 匹配重复/成对内容 | `(.)\1+` 匹配连续重叠字符 `aaa` |

### 4.5 锚点与边界

| 语法 | 含义 | 何时使用 | 示例 |
|------|------|----------|------|
| `^` | 提取值开头（整体开头，非每行行首） | 只处理开头前缀 | `^Bearer\s+` 去 Bearer 前缀 |
| `$` | 提取值结尾（整体结尾，非每行行尾） | 去尾部 / 结尾补内容 | `^(\d+)$` → `$1 条` |
| `\b` | 单词边界（字母数字与其它字符的交界） | 替换独立单词、避免误伤子串 | `\bok\b` 匹配 `ok` 但不匹配 `okok` |

### 4.6 环视断言（零宽，不消耗字符）

| 语法 | 含义 | 何时使用 | 示例 |
|------|------|----------|------|
| `(?=...)` | 正向先行：后面是 … | 在某内容**之前**插入 | `(?=\d)` 定位数字前 |
| `(?!...)` | 负向先行：后面不是 … | 排除特定后缀 | `\d+(?!%)` 匹配不带 `%` 的数字 |
| `(?<=...)` | 正向后行：前面是 … | 在某内容**之后**插入 | `(?<= total:)\d+` |
| `(?<!...)` | 负向后行：前面不是 … | 排除特定前缀 | `(?<!\d)\d` 匹配前面不是数字的数字 |

组合示例：表达式 `(?<=[a-zA-Z])(?=\d)`、替换为空格：`abc123` → `abc 123`（在字母与数字交界处插入空格，不改动原字符）。

### 4.7 或（多选一）

- 语法：裸竖线 `|`（写在字符类外），多段表达式任选其一匹配。
- 何时使用：多种写法、多个候选内容需要统一处理时。

```text
cat|dog               匹配 cat 或 dog
^(http|https)://      去除 http/https 协议前缀
^\s+|\s+$             匹配开头的空白 或 结尾的空白（去首尾空白）
```

**注意**：`|` 就是或，**不要**写成 `\|`——`\|` 匹配的是字面竖线字符，两者语义完全不同。本档 v1.0 曾在「或」条目与示例中误写为 `\|`，v2.0 起修正（见第七节对照）。

### 4.8 Unicode 与中文

| 语法 | 含义 | 何时使用 | 示例 |
|------|------|----------|------|
| `\uXXXX` | 4 位十六进制 Unicode 字符 | 匹配特定符号 | `\u00a9` 匹配 © |
| `\u{XXXXX}` | 码点形式的 Unicode 字符 | 部分旧引擎不支持，**建议优先使用 `\uXXXX`** | — |
| `[\u4e00-\u9fa5]` | 常用汉字范围 | 只保留/匹配中文 | `[^\u4e00-\u9fa5]+` 删除所有非中文 |

### 4.9 大小写处理

- 引擎默认**区分大小写**，系统只固定附加全局替换标志 `g`。
- 正式兼容写法是字符类逐位匹配：`[Tt]rue`、`[Oo][Kk]`、`^[Ss][Uu][Cc][Cc][Ee][Ss][Ss]:\s*`。
- 不要依赖 `(?i)` 或 `(?i:...)` 内联标志。内联标志不属于本功能保证支持的语法，可能被判定为非法规则并跳过。
- 全局替换（`g`）由系统自动附加，无需手动填写。

### 4.10 不支持 / 需注意的写法

- 不支持 `[\p{L}]` 等 Unicode 属性类（`\p{...}` 需要 `u` 标志，本功能未开启）。
- 表达式经内部转义扩展后以全局替换标志构造执行，**无需也不要**在首尾添加 `/` 定界符（写 `<br>` 而不是 `/<br>/`）。
- 逗号在 `{n,m}` 中不能带空格：`{2, 5}` 无效，应写 `{2,5}`。
- 未启用 `m`/`s` 标志：多行提取值中 `^`/`$` 只匹配整体首尾，`.` 不匹配换行（见第三节）。
- 过于宽泛的表达式（如裸 `.*`）配合非空替换可能产生意外结果，建议先小范围验证（见第十一节）。

## 五、替换字符串语法

「替换为」支持以下特殊序列，其余字符按字面输出：

| 序列 | 含义 | 何时使用 | 示例 |
|------|------|----------|------|
| `$1` … `$9` | 第 n 个捕获分组匹配的内容 | 保留片段、重排内容 | 表达式 `(\d{4})-(\d{2})-(\d{2})`，替换 `$1/$2/$3`：`2026-09-09` → `2026/09/09` |
| `$&` | **整个匹配**的内容 | 给匹配内容统一加包裹/前后缀 | 表达式 `\d+`，替换 `[$&]`：`a1b22` → `a[1]b[22]` |
| `` $` `` | 匹配内容之前的部分 | 取匹配前缀 | — |
| `$'` | 匹配内容之后的部分 | 取匹配后缀 | — |
| `$$` | 字面量 `$` | 替换结果中需要输出 `$` 本身 | 表达式 `元`，替换 `$$`：`100元` → `100$` |
| 留空 | 删除所有匹配内容 | 去除标签、空白、前缀 | 表达式 `<[^>]+>`，替换留空：`<b>hi</b>` → `hi` |

**注意**：JavaScript 方言中**没有 `$0`**；引用整段匹配用 `$&`。`$` 后跟未定义分组的数字（如只有 2 个分组时写 `$5`）按字面输出。

替换文本还会将 `\n`、`\t`、`\r`、`\\` 转换为真实换行、制表、回车和反斜杠；其他反斜杠序列保持原样。

完整示例：提取值 `status: OK`，表达式 `^(\w+):\s*(.+)$`，替换为 `$2 ($1)`，结果 `OK (status)`。

## 六、无效正则的处理

- 输入过程中表达式非法时，卡片中该行下方会即时提示「正则表达式无效，请检查语法」（逐条即时校验）。
- 发送请求时仍存在非法表达式的情况下，该条清理规则会被**自动跳过**（不中断请求、不影响其他规则，记录 warn 日志），提取值按未清理返回。
- 常见非法写法：未闭合的括号 `((\d+`、未闭合的字符类 `[a-z`、非法量词 `a{2,1}`（下界大于上界）、悬空的 `*` 或 `+`、非法的内联标志。

## 七、常见错误写法对照

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| `/<br>/` | 输入框只填表达式主体，不需要 `/` 定界符 | `<br>` |
| `{2, 5}` | 量词逗号后不能有空格 | `{2,5}` |
| `$0`（想引用整个匹配） | JS 方言中没有 `$0` | `$&` |
| `\p{L}` | Unicode 属性类需要 `u` 标志，本功能未开启 | `[a-zA-Z]` / `[\u4e00-\u9fa5]` |
| `<.*>`（去 HTML 标签） | 贪婪匹配会从第一个 `<` 吞到最后一个 `>` | `<[^>]+>` |
| `(?i)pattern` | 内联标志不是本功能保证支持的语法 | `[Pp][Aa][Tt][Tt][Ee][Rr][Nn]` |

含竖线「或」的写法对照（竖线在表格中易歧义，以代码块为准）：

```text
错误：cat\|dog      ← 反斜杠竖线 = 匹配字面字符 "cat|dog"，不是"或"
正确：cat|dog       ← 裸竖线才是"或"

错误：^\s+\|\s+$    ← 只能匹配「空白 + 字面竖线 + 空白」，去不了首尾空白
正确：^\s+|\s+$     ← 匹配开头空白或结尾空白

错误：^"+\|"+$      ← 只能匹配「引号 + 字面竖线 + 引号」
正确：^"+|"+$       ← 去除首尾引号
```

## 八、使用示例

以下示例均可在「正则清理」卡片中直接配置。

| 目标 | 作用规则名 | 正则表达式 | 替换为 | 输入 → 输出 |
|------|-----------|-----------|--------|------------|
| 去除 HTML 标签 | （留空） | `<[^>]+>` | （留空） | `<b>hi</b>` → `hi` |
| 只保留数字 | 订单号 | `\D+` | （留空） | `No.1024-x` → `1024` |
| 提取 Bearer 令牌 | token | `^Bearer\s+` | （留空） | `Bearer abc123` → `abc123` |
| 日期格式转换 | 时间 | `(\d{4})-(\d{2})-(\d{2})` | `$1/$2/$3` | `2026-09-09` → `2026/09/09` |
| 压缩连续空白 | （留空） | `\s+` | ` ` | `a   b` → `a b` |
| 只保留中文字符 | 备注 | `[^\u4e00-\u9fa5]+` | （留空） | `备注note:中文` → `备注中文` |
| 数字后补单位 | 数量 | `^(\d+)$` | `$1 条` | `1024` → `1024 条` |
| 去除 URL 域名 | 地址 | `^https?://[^/]+` | （留空） | `https://api.example.com/v1/user` → `/v1/user` |
| 千分位去逗号 | 金额 | `(\d),(\d)` | `$1$2` | `1,024,576` → `1024576` |
| 压缩重复字符 | （留空） | `(.)\1+` | `$1` | `aaaabbb` → `ab` |
| 字母数字间加空格 | （留空） | `(?<=[a-zA-Z])(?=\d)` | ` ` | `abc123` → `abc 123` |
| 匹配内容加方括号 | 版本 | `\d+(\.\d+)*` | `[$&]` | `v1.2.3` → `v[1.2.3]` |
| 忽略大小写去前缀 | 状态 | `[Ss][Uu][Cc][Cc][Ee][Ss][Ss]:\s*` | （留空） | `SUCCESS: done` → `done` |
| 独立单词替换 | 状态 | `\b[Oo][Kk]\b` | `成功` | `ok, okok` → `成功, okok` |

含竖线「或」的示例（同样以代码块为准，直接照抄即可）：

```text
去除首尾空白：  ^\s+|\s+$   替换留空    "  abc  " → "abc"
去除引号包裹：  ^"+|"+$     替换留空    "张三" → 张三
兼容两种前缀：  ^(v|V)\d    替换留空    v1.2.3 → 1.2.3
```

> 说明：
> - `只保留数字`：`\D+` 会删除所有非数字段落；若需严格「仅保留第一段连续数字」，使用表达式 `^.*?(\d+).*$`、替换为 `$1`（非贪婪 `.*?` 确保取到第一段）。
> - `独立单词替换`：`\b` 保证只替换独立单词，`okok` 内部的 `ok` 因无单词边界不会被误伤。
> - 上述代码块中的 `|` 是"或"，**不加** `\` 转义；只有匹配字面竖线字符时才写 `\|`（对照第七节）。

## 九、持久化与导入导出

### 9.1 数据库存储

清理规则随接口配置一起持久化到 RDB（`qovanta.db`；schema 通过 `PRAGMA user_version` 逐级迁移，当前版本 7；版本 6 引入条件分支链列、版本 7 引入接口级网络配置列，均不改变 `regex_clean_rule` 表结构）：

```text
表：regex_clean_rule
┌──────────────┬───────────┬────────────────────────────────┐
│ 字段          │ 类型      │ 说明                           │
├──────────────┼───────────┼────────────────────────────────┤
│ id           │ TEXT (PK) │ 规则 ID                        │
│ config_id    │ TEXT (FK) │ 关联 api_config.id，级联删除   │
│ sort_order   │ INTEGER   │ 执行顺序（=卡片列表顺序）      │
│ target_name  │ TEXT      │ 作用规则名，空串表示全部       │
│ pattern      │ TEXT      │ 正则表达式                     │
│ replacement  │ TEXT      │ 替换内容                       │
└──────────────┴───────────┴────────────────────────────────┘
```

- 保存接口配置时，清理规则与提取规则在同一事务中整体删除重建，`sort_order` 按卡片列表下标写入。
- 删除接口配置时，其清理规则级联删除。

### 9.2 导入 / 导出格式

导出文件使用严格格式 `format: "qovanta.backup"`、`version: 1`，顶层含 `exportedAt` 导出时间戳。每个配置项可包含 `regexCleanRules` 与 `conditionRules` 数组，提取规则带 `id` 并可含 `transforms` 转换链与可选 `source` 解析格式（`"JSON"` 或 `"HTML"`，缺省为 `"JSON"`）：

```json
{
  "format": "qovanta.backup",
  "version": 1,
  "exportedAt": 1758403200000,
  "configs": [{
  "name": "示例接口",
  "url": "https://api.example.com/user",
  "extractionRules": [
    { "id": "e1", "name": "用户名", "path": "$.data.name", "targetType": "VALUE" },
    { "id": "e2", "name": "时间", "path": "$.data.time", "targetType": "VALUE", "transforms": "timestampToDate" },
    { "id": "e3", "name": "标题", "path": "//h1[@class='title']/text()", "targetType": "VALUE", "source": "HTML" }
  ],
  "regexCleanRules": [
    { "targetName": "用户名", "pattern": "<[^>]+>", "replacement": "" }
  ],
  "conditionRules": [
    { "targetName": "时间", "op": "", "expected": "", "matchOutput": "", "unmatchOutput": "", "branches": "" }
  ]
  }],
  "chains": [],
  "envs": []
}
```

- `regexCleanRules`、`conditionRules`、`transforms` 均为可选字段；缺失时按空规则列表处理。
- 使用分支链的条件规则：条件逻辑编码在 `branches` 字段（控制字符分隔的紧凑编码），此时 `op` / `expected` / `matchOutput` / `unmatchOutput` 导出为空；旧备份不含 `branches` 时仍按旧单条件字段导入执行。
- 格式标识、版本或结构不匹配的备份会被拒绝，不兼容旧版备份格式。
- **导出脱敏**：认证字段与疑似凭据的请求头会被脱敏（仅保留 `{{...}}` 占位符引用，明文丢弃），密文环境变量以空值导出。
- 导入时提取规则复用导出的 `id`（缺失时生成新 UUID）；清理规则与条件规则始终生成新的 UUID，可与既有配置并存。

## 十、与其他功能的联动

| 功能 | 行为 |
|------|------|
| 响应卡片「提取结果」 | 展示清理后的值 |
| 首页接口卡片「提取结果」 | 自动请求 / 手动刷新后展示清理后的值 |
| 链式请求-步骤变量绑定 | 后续步骤引用的变量取清理后的值 |
| 链式请求-输出映射 / 输出模板 | 输出结果使用清理后的值 |
| 复制提取值 | 复制的是清理后的值 |
| 原始响应体 / 复制响应体 | 不受影响，始终为未清理的原始内容 |
| 其他等长数组提取结果 | 执行条件过滤某规则的数组元素时，其他等长数组结果按保留下标同步对齐（详见《执行条件文档》） |

> 提取结果的完整处理管线为：**JSON 提取 → 正则清理 → 数据转换 → 执行条件**（执行条件在全部规则处理完成后统一运行）。正则清理之后还可以对该规则配置链式数据转换（时间戳与日期互转、Base64 / URL 编解码等）和执行条件（条件判断、数组过滤、跨规则关联筛选），详见《提取规则文档》与《执行条件文档》。

## 十一、最佳实践

1. **先配置提取规则再配置清理规则**：清理规则依赖提取结果的文本内容，先用一次请求确认提取值的真实格式。
2. **善用作用范围**：多条提取规则共用接口时，优先用「作用规则名」限定范围，避免全局规则误伤其他提取值。
3. **小步验证**：复杂表达式拆成多条简单规则按顺序执行，比一条大表达式更易排查。
4. **警惕贪婪匹配**：处理 HTML 类内容时优先使用 `<[^>]+>` 而非 `<.*>`，避免跨标签吞噬内容；截取"第一段"时优先用非贪婪 `.*?`。
5. **优先受限写法**：避免裸 `.*` / `.+` 配合非空替换；避免嵌套量词（如 `(a+)+`）引发灾难性回溯，提取值较长时尤其注意。
6. **注意输入框填法**：只写表达式主体，不要加 `/.../` 定界符，也不要填 `g` 标志；`|` 表示"或"时不转义，匹配字面竖线才写 `\|`。
7. **大小写策略**：先确认提取值的真实大小写再写表达式；不确定时用字符类 `[Tt]`、`[Oo][Kk]` 兼容。
8. **改完即验证**：修改规则后重新发送请求，提取结果面板即时反映清理后的值，确认无误再保存。
