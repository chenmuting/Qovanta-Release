# 执行条件文档

---

## 一、功能概述

「执行条件」用于对**提取规则产生的提取结果**做条件判断，并按判断结果改写输出。它采用 **if / else if / else 分支链**模型：

- 一条执行条件规则 = 一组 `if / else if(可多个) / else` 分支链，作用于指定的提取规则（或全部）。
- 每个分支可包含**多个条件**，条件之间用「且(AND)」或「或(OR)」组合。
- 求值时按分支顺序判断，**命中首个成立的分支即输出其结果**并结束；其余分支不再判断。
- 分支输出留空：当条件成立、命中 `if` / `else if` 分支时，原样输出该值，即输出「过滤后的值」；仅当所有条件都不成立、由 `else` 兜底且输出留空时才「保留原值」；未配置 `else` 且条件不成立时「过滤该结果」。数组结果按元素判断并整体决定兜底与否，详见第四节。

处理链路：

```text
发送请求
  → 响应体
  → 提取规则（JSON / HTML 提取，见《提取规则文档》）
  → 正则清理（RegexCleanRule）
  → 值转换（时间/编解码/格式化等）
  → 执行条件（ConditionRule，本文档环节）   ← 条件判断与输出改写
  → 提取结果展示 / 链式请求变量绑定、输出映射
```

**重要**：执行条件只作用于**提取结果**，不修改原始响应体，也不影响请求发送内容。

**执行时机**：所有提取规则先各自完成提取 → 正则清理 → 值转换，随后执行条件在第二趟**统一运行**，且仅对提取成功的结果生效——这正是跨规则数组对齐（第四节）的前提。一条提取结果命中多条执行条件规则时，按规则列表顺序**串行应用**，前一条的输出作为后一条的输入。

## 二、分支链模型

一条规则由「作用规则名」+「分支链」组成。

### 2.1 作用规则名（targetName）

- 填写某条提取规则的名称：该执行条件只作用于同名提取结果（**区分大小写，需完全一致**）。
- **留空**：对全部提取结果生效。

### 2.2 分支类型

| 分支 | 说明 | 是否可删 |
|------|------|----------|
| `如果 if` | 分支链的首个分支，必有且唯一 | 否 |
| `否则如果 else if` | 位于 if 与 else 之间，可添加多个 | 是 |
| `否则 else` | 兜底分支，位于末尾，无条件恒成立 | 是 |

- 新建规则时默认生成 `if`（1 个条件）+ `else`（无条件）两个分支。
- 点击「添加 else if 分支」会在 `else` 前插入一个 else if 分支；`else` 已被删除时则追加到分支链末尾。
- `else` 分支没有条件，只有输出；一旦到达即命中。

### 2.3 分支内的条件与组合

- 每个 `if` / `else if` 分支可包含一个或多个**条件**（clause）。
- 多个条件通过分支的「多条件组合」选择器组合：
  - **且（全部满足）**：所有条件都成立，分支才成立。
  - **或（任一满足）**：任一条件成立，分支即成立。
- 单个条件时不显示组合选择器。

### 2.4 分支输出

- 命中的分支若「输出」非空，则提取结果被替换为该输出（支持 `{{fn:...}}` 动态函数）。
- 当条件成立、命中的 `if` / `else if` 分支输出为空：原样输出该值，作为**过滤后的结果**。
- 仅当所有条件都不成立、由 `else` 兜底且输出为空：**保留原值**不变（规则不生效）。
- 未配置 `else` 且条件不成立：该结果被**过滤**（置空并移除）。
- 数组结果的「过滤」「兜底」按元素判断并整体决定，见第四节。

## 三、条件运算符

条件由「运算符 + 期望值」组成，共 11 种运算符：

| 运算符 | 标识 | 是否需要期望值 | 说明 |
|--------|------|----------------|------|
| 等于 | `eq` | 是 | 字符串完全相等 |
| 不等于 | `ne` | 是 | 字符串不相等 |
| 包含 | `contains` | 是 | 值包含期望子串（期望为空视为成立）|
| 不包含 | `notContains` | 是 | 值不包含期望子串（期望为空同样视为成立）|
| 正则匹配 | `regex` | 是 | 期望作为正则，`test(value)` 命中 |
| 为空 | `isEmpty` | 否 | 去除首尾空白后长度为 0 |
| 不为空 | `notEmpty` | 否 | 去除首尾空白后长度大于 0 |
| 大于 | `gt` | 是 | 数值比较，`value > 期望` |
| 小于 | `lt` | 是 | 数值比较，`value < 期望` |
| 大于等于 | `gte` | 是 | 数值比较，`value >= 期望` |
| 小于等于 | `lte` | 是 | 数值比较，`value <= 期望` |

说明：

- 数值比较会将两侧转换为数值；任一侧非数字则比较不成立。
- 正则非法时该条件视为不成立；编辑器会对非法正则给出提示（含 `{{fn:` 的动态期望不做静态校验）。
- `为空` / `不为空` 不需要期望值，编辑器会隐藏期望输入框。
- 分支的条件被全部删除后，该分支**恒不成立**；请为每个 `if` / `else if` 分支至少保留一个条件。

## 四、单值与数组的处理

执行条件对提取结果的单值与数组分别处理（`ExtractDataUseCase.applyBranchCondition`）：

- **单值**：对该值走一遍分支链，按命中分支输出改写；命中 if / else if 分支且输出为空则原样输出该值（过滤后的结果），命中 else 且输出为空则保留原值；仅当无分支命中（未配置 else）时该结果置空并标记提取失败（`success=false`）。
- **数组**：对**每个元素**独立走分支链。命中 `if` / `else if` 的元素：输出留空则原样保留（过滤后的结果），非空则改写。未命中的元素：`else` 输出非空则改写为 `else` 输出；`else` 输出留空时——若整个数组**没有任何元素**命中过 `if` / `else if`（所有条件不成立），保留整个原数组原值（规则不生效），否则这些元素被**过滤**；未配置 `else` 时直接被过滤。数组长度可能变短；全部元素被过滤时该结果标记提取失败。
- **关联对齐**：若规则指定了作用规则名且数组发生过滤，其他等长度数组结果会按保留下标同步对齐（`alignCorrelatedResults`），保证多条数组结果按行一一对应。

> 版本演进：2.0 版分支模型曾「永远保留原值、不改数组长度」；2.1 曾将 `else` 输出留空与无分支命中均视为过滤；2.2 将留空分支统一为原样输出；2.3 明确「过滤后的值 / 保留原值」语义区分。2.4 起数组兜底改为整体判断：仅当整个数组没有任何元素命中 `if` / `else if` 时，`else` 留空才保留整个原数组；只要有元素命中，落到 `else` 留空的元素一律被过滤。历史遗留旧规则的「不满足时输出留空」在转换为分支链时不再生成 else 分支，从而保持原有过滤行为不变。

## 五、动态函数支持

期望值与分支输出都支持 `{{fn:...}}` 动态函数，执行时渲染为实际值，例如：

- `{{fn:timestamp}}`：当前时间戳（秒级；毫秒级用 `{{fn:timestampMs}}`）
- `{{fn:datetime:yyyy-MM-dd HH:mm:ss}}`：格式化时间
- `{{fn:timestamp-300}}`：当前时间戳偏移

典型用法：将提取到的过期时间与当前时间比较，判断是否失效。详见《占位符使用文档》动态函数章节。

接口编辑页顶栏菜单提供「**函数测试**」工具：输入 `{{fn:...}}` 表达式即可在发送请求前预先查看实际求值结果，便于编写期望值与分支输出。

## 六、使用示例

### 示例 1：状态码映射为文案

作用规则名：`status`

| 分支 | 条件 | 输出 |
|------|------|------|
| if | 等于 `200` | `成功` |
| else if | 等于 `404` | `资源不存在` |
| else if | 等于 `500` | `服务器错误` |
| else | —— | `未知状态 ` |

结果：提取到 `200` → 输出 `成功`；提取到 `404` → 输出 `资源不存在`。

### 示例 2：多条件「且」组合

作用规则名：`token`，某分支组合选「且」：

| 分支 | 条件（且） | 输出 |
|------|-----------|------|
| if | 不为空 + 包含 `Bearer ` | 过滤后的值（留空）|
| else | —— | `令牌无效` |

结果：token 非空且以 `Bearer ` 开头 → 原样输出过滤后的值；否则输出 `令牌无效`。

### 示例 3：多条件「或」组合

作用规则名：`level`，分支组合选「或」：

| 分支 | 条件（或） | 输出 |
|------|-----------|------|
| if | 等于 `error` 或 等于 `fatal` | `严重` |
| else | —— | `正常` |

### 示例 4：数值区间判断

作用规则名：`score`

| 分支 | 条件 | 输出 |
|------|------|------|
| if | 大于等于 `90` | `优秀` |
| else if | 大于等于 `60` | `及格` |
| else | —— | `不及格` |

### 示例 5：与当前时间比较（动态函数）

作用规则名：`expireAt`

| 分支 | 条件 | 输出 |
|------|------|------|
| if | 小于 `{{fn:timestamp}}` | `已过期` |
| else | —— | `有效` |

## 七、编辑操作

在接口编辑页「执行条件」分段：

1. 点击卡片右上角「+」新增一条执行条件规则（默认含 if + else）。
2. 填写「作用规则名」，留空对全部提取结果生效。
3. 在 `if` / `else if` 分支中：
   - 「添加条件」可增加该分支的条件；多条件时选择「且/或」组合。
   - 每个条件选择运算符并填写期望值（`为空`/`不为空` 无需期望值）。
4. 填写各分支「输出」：if / else if 分支留空输出过滤后的值；else 分支留空时，若所有条件不成立则保留原值，若有元素命中则未命中的元素被过滤。
5. 「添加 else if 分支」在 else 前插入分支；`else if` 与 `else` 分支可删除。
6. 规则可整体删除。

## 八、数据与兼容性

- 分支链持久化在 `condition_rule` 表的 `branches` 列（数据库版本 6 引入；当前数据库版本为 7，版本 7 新增的接口级网络配置列与执行条件无关），采用控制字符分隔的紧凑编码。
- 导入导出：`branches` 为可选字符串字段；旧备份不含该字段时按旧的单条件规则导入。
- 旧规则（`branches` 为空）在编辑时自动转换为分支视图：`if(旧条件)→满足输出`；「不满足时输出」非空时追加 `else→不满足输出`，为空时不生成 else（保持旧规则的过滤行为）。
- 求值阶段：有分支的规则走新分支链逻辑，无分支的历史规则继续走旧逻辑，两者并存互不影响。

## 九、常见问题

**Q1：为什么设置了条件却没有生效？**
确认「作用规则名」与目标提取规则名一致（或留空对全部生效），且提取规则本身提取成功。

**Q2：多个 else if 的判断顺序？**
严格按分支从上到下顺序判断，命中首个成立分支即停止，后续分支不再评估。

**Q3：分支输出留空会怎样？**
条件成立、命中 if / else if 分支时留空，原样输出该值，即输出过滤后的值；仅当所有条件都不成立、由 `else` 兜底且留空时才保留原值（常用于「只在不满足时改写」的场景，如示例 2）。数组中只要有元素命中，落到 `else` 留空的其余元素会被过滤。

**Q4：数组结果会被过滤吗？**
会。未配置 `else` 时未命中的元素被过滤；配置了 `else` 且输出非空时未命中的元素被改写；配置了 `else` 且输出留空时，若整个数组没有任何元素命中 `if` / `else if`，则保留整个原数组，否则未命中的元素被过滤。过滤发生后数组长度可能变短，并会同步对齐其他等长度数组结果。

**Q5：期望值可以引用其它提取结果吗？**
不能。执行条件的期望值是字面量或 `{{fn:...}}` 动态函数；跨步骤/跨规则的取值请使用串联链的变量绑定与占位符。
