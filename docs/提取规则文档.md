# 提取规则文档

---

## 一、功能概述

「提取规则」用于从**接口响应体**中按路径抽取需要的数据。每条规则包含名称、解析格式（`source`）与路径表达式（`path`）三部分。发送请求得到响应体后，系统按规则的解析格式分发到对应解析器：

- `JSON`：使用 JSON 路径语法（类 JSONPath 子集）；
- `HTML`：使用标准 XPath 1.0 语法。

提取得到的结果会继续进入正则清理、值转换、条件判断等二次处理环节，并最终展示在接口编辑页的响应面板、首页卡片与独立的接口结果页（「提取结果 / 可视化」双页签，可视化组合按接口持久化），或作为链式请求的变量参与后续步骤。提取失败的规则会跳过后续的清理、转换与条件判断；执行条件在全部规则完成提取与二次处理后统一运行，因此支持跨规则的数组对齐（详见《执行条件文档》）。

> 当数组结果被串联链后续步骤引用时，是否弹出选择面板由来源步骤的完整提取结果决定：混有单值与数组（或数组仅一个元素）时整体按单值处理；全部为等长数组时按行对齐选择，选中后按行迭代执行后续步骤；长度不等时依次弹出各组选择面板。详见《占位符使用文档》串联链变量一节。

处理链路：

```text
发送请求
  → 响应体
  → 提取规则（ExtractionRule，按 source 分发 JSON / HTML 解析）   ← 本文档环节
  → 正则清理规则（RegexCleanRule）
  → 值转换 / 条件判断
  → 提取结果展示（响应面板 / 首页卡片 / 接口结果页：提取结果 + 可视化）
  → 链式请求变量绑定、输出映射
```

**重要**：提取规则只读取响应体，不修改任何请求内容；单条规则解析失败时可通过 `?? 默认值` 兜底（见第四节）。

## 二、通用规则

以下约定对 JSON 与 HTML 两种格式均适用。

### 2.1 默认值语法 `?? 默认值`

在路径末尾追加 `??` 与默认值，当提取失败（路径不存在、类型不符、解析异常）时返回该默认值。

| 示例 | 含义 |
|------|------|
| `data.token ?? 无` | 取不到 token 时返回「无」 |
| `//h1/text() ?? 默认标题` | 取不到标题时返回「默认标题」 |
| `data.list[].count ?? 0` | 数组不存在时返回「0」 |

- 分隔符是**第一个顶层** `??`（HTML 下会跳过引号与 `[]`/`()` 内的字符），其左侧为路径、右侧为默认值。
- 默认值可以为空（`path??`），表示失败时返回空字符串且规则仍算「成功」。
- JSON 与 HTML 均统一使用 `??`。在标准 XPath 中 `|` 是并集（union）运算符，不能再作默认值分隔符。


### 2.2 结果类型

提取结果分为单值与多值：

- **单值（VALUE）**：命中唯一结果，直接返回文本。
- **数组（ARRAY）**：命中多个结果，`value` 用换行 `\n` 连接，同时保留 `values` 数组供链式请求逐项使用。
- **计数（COUNT）** / **存在（EXISTS）**：返回数量或 `true`/`false`。

### 2.3 文本处理

- JSON 字符串值会自动去除首尾引号并反转义（`\n`、`\t`、`\uXXXX`、代理对等）。
- HTML 取出的文本会**归一化空白**：连续空白折叠为单个空格并 trim，`<br>` 转为空格，并解码常见 HTML 实体。

### 2.4 批量拆分多条规则

路径输入框支持一次粘贴**多行路径**（每行一条）：保存时非空行多于 1 行会自动拆分——第 1 行保留在当前规则，其余每行各生成一条新规则，名称与解析格式沿用当前规则。适合从接口文档一次性搬运多个字段路径。

## 三、JSON 提取语法

目标类型由路径后缀自动推断，无需手动选择。

### 3.1 根与对象字段

| 语法 | 含义 | 示例 |
|------|------|------|
| `$` | 根节点自身 | `$` → 整个响应体 |
| `$.field` | 根下的字段（`$.` 可省略） | `$.code` 等价于 `code` |
| `a.b.c` | 逐级访问对象字段 | `data.user.name` |

- `$` 或 `$.` 前缀会被归一化去除。
- 字段名通过精确匹配 `"key"` 定位，区分大小写。

示例响应：

```json
{ "code": 0, "data": { "user": { "name": "Ada", "age": 30 } } }
```

| 路径 | 结果 |
|------|------|
| `code` | `0` |
| `data.user.name` | `Ada` |
| `data.user.age` | `30` |

### 3.2 数组下标

用 `[n]` 访问数组第 n 个元素（下标从 0 开始）。可紧跟字段名，也可对根数组直接取值。

| 语法 | 含义 |
|------|------|
| `list[0]` | list 数组第 1 个元素 |
| `data.items[2].id` | items 第 3 项的 id 字段 |
| `[0]` | 根数组第 1 个元素 |

示例响应：

```json
{ "list": [ { "id": "a1" }, { "id": "b2" }, { "id": "c3" } ] }
```

| 路径 | 结果 |
|------|------|
| `list[0].id` | `a1` |
| `list[2].id` | `c3` |

### 3.3 数组展开 `[]`（取整组）

在数组路径末尾加 `[]`，表示取出该数组的**全部元素**，返回数组结果（ARRAY）。

| 语法 | 含义 |
|------|------|
| `data[]` | 取 data 数组的所有元素 |
| `data.ids[]` | 取 data.ids 数组的所有元素 |

示例响应：

```json
{ "data": ["a1", "b1", "a2"] }
```

| 路径 | 结果（换行连接） |
|------|------|
| `data[]` | `a1` / `b1` / `a2` 三项 |

### 3.4 数组字段展开 `[].key`（批量取字段）

对**对象数组**，在 `[]` 后加 `.字段名`，可批量取出每个对象的该字段，返回数组（ALL_KEYS）。

示例响应：

```json
{ "list": [ { "id": "a1", "name": "甲" }, { "id": "b2", "name": "乙" } ] }
```

| 路径 | 结果 |
|------|------|
| `list[].id` | `a1` / `b2` |
| `list[].name` | `甲` / `乙` |

- 某个元素缺少该字段时会跳过该项。
- `[].count`、`[].exists`、`[].keys`、`[].values`、`[].*` 属于保留后缀，不作为普通字段展开。

### 3.5 键名提取 `[].keys`

在对象路径末尾加 `[].keys`，取出该对象的**全部键名**，返回数组结果。

| 路径 | 含义 |
|------|------|
| `data[].keys` | data 对象的全部键名 |
| `$.meta[].keys` | meta 对象的全部键名 |

示例响应：

```json
{ "data": { "token": "t1", "uid": "u1" } }
```

| 路径 | 结果（换行连接） |
|------|------|
| `data[].keys` | `token` / `uid` |

- 目标也可以是**对象数组**：`list[].keys` 会依次取出数组内每个对象的键名并合并为一个数组（非对象元素跳过）。
- 仅取直接键名，不递归嵌套对象。
- 对象为空、目标不存在或目标不是对象/对象数组时提取失败，可用 `?? 默认值` 兜底。

### 3.6 键值提取 `[].values`

在对象路径末尾加 `[].values`，取出该对象的**全部值**，返回数组结果。

| 路径 | 含义 |
|------|------|
| `data[].values` | data 对象的全部值 |
| `list[].values` | 数组内每个对象的值（合并为一个数组） |

示例响应：

```json
{ "data": { "code": 0, "name": "Ada", "ok": true } }
```

| 路径 | 结果（换行连接） |
|------|------|
| `data[].values` | `0` / `Ada` / `true` |

- 字符串值会自动去引号并反转义；嵌套对象/数组作为原始 JSON 文本返回。
- 某个键的值缺省（如空对象）或目标不存在时提取失败，可用 `?? 默认值` 兜底。

### 3.7 计数 `[].count`

在数组路径末尾加 `[].count`，返回数组元素个数（COUNT）。

| 路径 | 含义 |
|------|------|
| `data[].count` | data 数组长度 |
| `data.list[].count` | data.list 数组长度 |

示例：`{ "data": ["a1","b1","a2"] }` → `data[].count` = `3`。

- 若目标不是数组，返回空或默认值。

### 3.8 存在判断 `[].exists`

在路径末尾加 `[].exists`，判断目标是否存在，返回 `true` / `false`（EXISTS）。

| 路径 | 含义 |
|------|------|
| `data.token[].exists` | token 是否存在 |
| `data.list[].exists` | list 是否存在 |

- 判断依据是「原始值非空」。

### 3.9 JSON 语法速查

| 语法 | 目标类型 | 说明 |
|------|----------|------|
| `$` / 空 | VALUE | 根节点 |
| `a.b.c` | VALUE | 逐级字段 |
| `arr[n]` | VALUE | 数组下标 |
| `arr[n].key` | VALUE | 下标后取字段 |
| `arr[]` | ARRAY | 取整个数组 |
| `arr[].key` | ALL_KEYS | 批量取对象字段 |
| `obj[].keys` | KEYS | 取对象的全部键名（对象数组时逐元素合并） |
| `obj[].values` | VALUES | 取对象的全部值（对象数组时逐元素合并） |
| `arr[].count` | COUNT | 数组长度 |
| `arr[].exists` | EXISTS | 是否存在 |
| `path ?? 默认值` | — | 失败兜底 |

## 四、HTML 提取语法（标准 XPath 1.0）

HTML 解析采用符合 **XPath 1.0 核心规范** 的求值引擎：支持 13 条轴、缩写语法、完整的表达式文法（逻辑/比较/算术/并集运算）、节点测试与核心函数库。HTML 场景无命名空间（`namespace::` 恒为空集，`local-name()` 与 `name()` 等价）。

> 与旧版「自研子集」相比的两处行为变化：
> - `|` 现在是标准**并集（union）**运算符；默认值兜底改用 `?? 默认值`（见 2.1）。
> - `text()` 恢复标准语义，仅选择**直接子文本节点**；要取整个元素的全部文本，请用裸节点步（如 `//p`）或函数 `string()` / `normalize-space()`。

### 4.1 整体结构

```text
XPath 表达式 ?? 默认值
```

- 表达式为合法 XPath 1.0 表达式（定位路径、函数调用、运算表达式等），非法表达式判定为提取失败。
- 末尾可选 `?? 默认值` 兜底（在表达式字符串内的引号与括号中出现的 `??` 不会被当作分隔符）。

### 4.2 轴（全部 13 条）

| 轴 | 缩写 | 含义 |
|------|------|------|
| `child::` | 默认（省略即 child） | 直接子节点 |
| `descendant::` | — | 所有后代 |
| `descendant-or-self::` | `//` | 自身与所有后代 |
| `parent::` | `..` | 父节点 |
| `ancestor::` | — | 所有祖先 |
| `ancestor-or-self::` | — | 自身与所有祖先 |
| `following-sibling::` | — | 之后的同级节点 |
| `preceding-sibling::` | — | 之前的同级节点 |
| `following::` | — | 文档中其后的节点（不含后代） |
| `preceding::` | — | 文档中其前的节点（不含祖先） |
| `attribute::` | `@` | 属性 |
| `self::` | `.` | 自身 |
| `namespace::` | — | 命名空间（HTML 恒空） |

缩写：`//` = `/descendant-or-self::node()/`，`.` = `self::node()`，`..` = `parent::node()`，`@x` = `attribute::x`。

### 4.3 节点测试

- 名称测试：标签名（HTML 统一按小写比较）、`*` 通配。属性轴上的名称测试匹配属性。
- 类型测试：`node()`（任意节点）、`text()`（文本节点）、`comment()`（注释）、`processing-instruction()` / `processing-instruction('target')`。

### 4.4 谓词 `[...]`（过滤条件）

谓词是任意 XPath 表达式，可串联多个 `[..][..]`，按顺序过滤。常见用法：

| 谓词 | 含义 | 示例 |
|------|------|------|
| `[n]` | 位置等于 n（相对各上下文节点计数） | `//ul/li[2]` |
| `[last()]` / `[last()-1]` | 末位 / 倒数第二 | `//li[last()]` |
| `[position() > 1]` | 位置大于 1 | `//li[position()>1]` |
| `[@attr]` | 属性存在 | `//a[@href]` |
| `[@attr='v']` / `[@attr!='v']` | 属性等于 / 不等于 | `//div[@class='item']` |
| `[contains(@attr,'v')]` | 属性包含子串 | `//div[contains(@class,'card')]` |
| `[starts-with(@attr,'v')]` | 属性以 v 开头 | `//a[starts-with(@href,'/a')]` |
| `[@a='x' and @b='y']` | 多条件与 | `//input[@type='text' and @name='q']` |
| `[@a='x' or @b='y']` | 多条件或 | `//p[@class='a' or @class='b']` |
| `[not(@class='active')]` | 取反 | `//a[not(@class='active')]` |
| `[text()='值']` | 直接文本等于 | `//li[text()='首页']` |

说明：

- 位置是**相对于上下文节点**选出的节点集计数（例如 `//ul/li[2]` 取每个 `ul` 下第 2 个 `li`），这与标准 XPath 一致。
- `@attr != 'v'`：标准语义下，`@attr` 不存在时为**空节点集**，与字符串比较恒为假；要匹配「没有该属性或属性不等于」，请用 `not(@attr='v')`。
- 属性值与字符串字面量必须用单/双引号包裹。
- 支持 `and` / `or`、比较运算（`= != < <= > >=`）、算术运算（`+ - * div mod`）与并集 `|`。

### 4.5 取值步（末尾决定取什么）

| 写法 | 含义 |
|------|------|
| `.../text()` | 直接子文本节点（可能多个） |
| `.../@attr` | 属性值 |
| 裸节点步（如 `//p`） | 节点的 string-value（元素为其全部后代文本的拼接） |
| `string(路径)` / `normalize-space(路径)` | 显式取字符串 / 归一化空白 |

示例：

- `//h1` → 标题的完整文本
- `//a[@class='next']/@href` → 链接地址
- `//p/text()` → `p` 的直接文本节点（不含子元素内文本）
- `string(//p)` → `p` 的完整文本

### 4.6 核心函数库

节点集：`last()` `position()` `count()` `id()` `local-name()` `namespace-uri()` `name()`
字符串：`string()` `concat()` `starts-with()` `contains()` `substring-before()` `substring-after()` `substring()` `string-length()` `normalize-space()` `translate()`
布尔：`boolean()` `not()` `true()` `false()` `lang()`
数值：`number()` `sum()` `floor()` `ceiling()` `round()`

表达式结果为节点集时按匹配节点返回（单个为值、多个为数组）；为数字 / 布尔 / 字符串时直接返回对应文本（如 `count(...)`、`boolean(...)`、`string-length(...)`）。

### 4.7 解析器容错与限制

- 自动处理注释 `<!-- -->`、`<!doctype>`、`<?...?>`（注释与 PI 作为节点保留，可被 `comment()` / `processing-instruction()` 选中）。
- 正确处理自闭合标签、void 标签（`br/img/input` 等）、原始文本标签 `script`/`style`。
- 支持常见标签的隐式闭合：`li/p/option/dt/dd` 同名互闭，以及 `td/th/tr` 表格结构。
- 安全上限：最多解析 20000 个节点，单段文本最长 512KB。
- 取出的文本在最终输出时会**归一化空白**（连续空白折叠为单空格并 trim）；表达式内需精确控制时可显式使用 `normalize-space()`。

### 4.8 HTML 语法速查

```text
//title/text()                                 页面标题
//div[@class='price']/text()                   指定 class 的价格文本
//a[@id='download']/@href                      下载链接地址
//ul[@class='list']/li/text()                  列表所有项（数组）
//div[contains(@class,'card')]//h3             卡片标题（整文本）
//li[last()]/a/text()                          每组列表最后一项的链接文本
//a[not(@class='active')]/@href                非 active 的链接
//a[starts-with(@href,'/a')]/text()            以 /a 开头的链接文本
//li[text()='b']/parent::ul/@class             命中项所在 ul 的 class
//p[@class='x']/following-sibling::p/text()    其后的同级段落
//tr[2]/td[1]/text()                           每个表格第 2 行第 1 格
//a[1]/@href | //a[2]/@href                    并集：前两个链接地址
count(//div[@class='item'])                    条目数量
boolean(//span[@class='sold-out'])             是否售罄
normalize-space(//h1)                          归一化后的标题
//meta[@name='keywords']/@content ?? 无        带默认值兜底
```

## 五、JSON 与 HTML 对比

| 能力 | JSON | HTML |
|------|------|------|
| 逐级定位 | `a.b.c` | `/a/b/c`、`//c` |
| 下标/位置 | `arr[n]` | `elem[n]`（按父分组） |
| 取整组 | `arr[]` | 多命中自动返回数组 |
| 批量取字段/属性 | `arr[].key` | `//elem/@attr`、`//elem/text()` |
| 键名提取 | `obj[].keys` | 不支持 |
| 键值提取 | `obj[].values` | `//elem/@*`（全部属性值） |
| 计数 | `arr[].count` | `count(路径)` |
| 存在判断 | `arr[].exists` | `boolean(路径)` |
| 条件过滤 | 不支持 | 完整谓词表达式：`and`/`or`、`= != < <= > >=`、`+ - * div mod`、`not(...)`、`contains/starts-with` 等 |
| 并集 | 不支持 | `路径A \| 路径B` |
| 默认值 | `path ?? 默认值` | `path ?? 默认值` |

## 六、常见问题

**Q1：路径取不到值？**
先确认解析格式（`source`）是否与响应体一致（JSON 响应用 JSON、网页用 HTML）；再检查路径大小写、引号是否正确。可临时加 `?? 调试值` 观察是否走了默认值分支。

**Q2：HTML 属性等值不生效？**
属性值必须加引号：`//a[@class='btn']`，写成 `//a[@class=btn]` 会导致整条表达式无效。另外注意 `@class != 'active'` 在属性不存在时为假，若要包含「无该属性」的节点请用 `//a[not(@class='active')]`。

**Q3：`//li[2]` 的位置如何计数？**
位置相对于上下文节点选出的节点集计数（标准 XPath 语义）。例如 `//ul/li[2]` 取每个 `ul` 下的第 2 个 `li`；要全局定位可用更精确的父级，如 `//ul[@id='main']/li[2]`。

**Q4：想批量拿到对象数组里的某个字段？**
JSON 用 `list[].字段名`（如 `list[].id`）；HTML 用 `//项容器/子元素/text()` 或 `/@attr`，多命中会自动返回数组。

**Q5：提取到的字符串带引号或转义？**
JSON 字符串已自动去引号并反转义；若仍需进一步清洗（如去 HTML 标签、截取分组），使用「正则清理」二次处理（见《正则规则文档》）。
