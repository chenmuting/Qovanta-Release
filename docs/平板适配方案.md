# Qovanta 平板适配说明

> 文档定位：已实施说明（原《平板适配方案》已于 1.2.0 版本落地，本文描述实际实现，供回归验收与后续迭代参考）
> 更新日期：2026-10-25
> 目标设备：HarmonyOS Phone + Tablet + 2in1（一套代码、一个 HAP）

---

## 1. 背景与结果

应用曾仅声明 `phone` 设备（`entry/src/main/module.json5` 中 `deviceTypes: ["phone"]`），按官方兼容运行规则，在平板上以兼容模式（9:18 或 1:1 竖屏小窗）运行，无法利用大屏。

1.2.0 起完成多设备适配，实际结果：

1. `deviceTypes` 声明 `["phone", "tablet", "2in1"]`，平板 / 2in1 以**原生形态**分发（全屏、横竖屏、分屏、自由多窗、悬浮窗）。
2. 遵循"一次开发，多端部署"部署模型 A：手机、平板、2in1 同泛类，**一套代码、一次编译、同一 HAP**，未拆分 products 层。
3. 以窗口宽度断点（SM / MD / LG）驱动布局：断点面向窗口而非设备，同一平板在分屏 / 自由窗口下落入不同断点时布局自动切换，不判设备类型。
4. 手机（SM）体验零回归：所有 `<600vp` 窗口维持原底部页签与单列布局，大屏行为收口在 `shared/ui-kit` 公共组件与 `pages/Index.ets`，业务页少感知。
5. 2in1 增量：Split 右栏内容不再限宽、按右栏实际宽度自适应双列 / 单列；补齐键鼠 hover、焦点与常用快捷键。

## 2. 断点系统（`shared/state/BreakpointSystem.ets`）

采用官方推荐方式：`uiContext.getWindowWidthBreakpoint()` + `window.on('windowSizeChange')` 监听。

- 导出枚举 `AppWidthBreakpoint { SM, MD, LG }`：系统 WIDTH_MD 折叠为 MD，WIDTH_LG / WIDTH_XL 折叠为 LG，其余（含 XS）为 SM；
- 断点值写入 `AppStorage('windowWidthBp')`，窗口实际宽度（vp，经 `px2vp` 取整）写入 `AppStorage('windowWidthVp')`，各页面通过 `@StorageLink` 读取；
- 提供语义方法 `isWide()`（≠SM）与 `isLarge()`（LG），以及 `current()` / `windowWidthVp()` / `refresh()`；
- `pages/Index.ets` 监听断点变化发布 `splitLayout` 标志（仅 LG 为 true），供 `AppContentSizer` / `AppAdaptiveContent` 消费；
- 自由窗口拖拽过程中连续刷新；单文件独立，阈值折叠为纯函数可单测。

## 3. 导航布局（`pages/Index.ets`）

| 断点 | 页签形态 | 导航模式 |
| --- | --- | --- |
| SM（手机 / 小窗） | 底部悬浮页签：`barPosition(End)`、`barFloatingStyle`（悬浮光感）、`barOverlap(true)` | `NavigationMode.Stack` |
| MD（平板竖屏 / 分屏） | 侧边页签：`vertical(true)`、`barPosition(Start)`、`barOverlap(false)`，不使用悬浮样式 | `NavigationMode.Stack` |
| LG（平板横屏 / 2in1 大窗） | 侧边页签（同 MD） | `NavigationMode.Split`：左栏主页 + 右栏 NavDestination |

- Split 下 `navBarWidth` 默认 320vp，窗口 ≥1440vp 时收敛为 360vp；`navBarWidthRange` 300~420vp，`minContentWidth(320)`，避免 2in1 大窗下左栏固定过宽挤压右栏；
- 子页面路由仍为 `NavPathStack.pushPath` + `IndexPageMap.ets`（AddPage、HomeResultPage、ChainDetailPage、ChainEditPage、GeneralPage、PersonalizationPage、AboutPage、DataClearPage、LogPage、DataBackupPage 共 10 个 NavDestination），LG 下在 Split 右栏展示，MD 下全屏压栈；
- 顶栏菜单（扫码 / 分组 / 新增 / 多选全选、分组、删除）与页签切换逻辑在各形态下复用；多选通过 AppStorage 令牌与各标签页通信；
- 断点切换时保持当前页签与路由状态连续。

## 4. 宽屏内容组件（`shared/ui-kit`）

| 组件 | 职责 |
| --- | --- |
| `AppContentSizer` | 缩进布局：内容限宽 `app.float.content_max_width` 且水平居中；读取 `splitLayout`，Split 下放宽为 100% 不限宽 |
| `AppAdaptiveContent` | 按实际宽度自适应列数：`onAreaChange` 测量可用宽度（Split 下按窗口宽减去 320vp 导航栏估算），≥`APP_ADAPTIVE_TWO_COLUMN_MIN_WIDTH`（640vp）向 `content(columns)` 回调 2 列，否则 1 列；`allowTwoColumnInSplit` 控制 Split 下是否允许双列；宽窗口时限宽 100%，SM 仍按 `content_max_width` |
| `AppList` | 重复布局：`autoLanes` + `minLaneWidth`（360vp）按列表实际宽度自动 1/2 列；`lanes` / `laneGutter` 支持固定多列；LazyForEach 数据源不变 |
| `AppSheet` | 跟手半模态：SM 为底部抽屉（detents）；MD/LG（`windowWidthBp ≠ SM`）为居中弹窗（`preferType: POPUP`），宽度 `app.float.sheet_popup_width`，高度按 `sheet_popup_height_large` / `sheet_popup_height_medium` |

落地页面：

- `AppAdaptiveContent`：DataBackupPage、AboutPage、DataClearPage、GeneralPage、PersonalizationPage、SettingsPage；
- `AppList autoLanes`：HomeListPanel（首页）、ChainListPanel（串联链）、EnvVariableListPanel（环境变量）、PresetVariablePanel（预设变量）、LogPage；
- AddPage（AddConfigSegment）与 ChainEditPage 直接引用 `APP_ADAPTIVE_TWO_COLUMN_MIN_WIDTH` 常量，内容宽度 ≥640vp 时表单 / 步骤双栏排布，窄宽度保持单列；
- 全部 Sheet Content（结果、图表、分组选择、扫码、JSON 选择器、运行时参数等）经 AppSheet 的 POPUP 化自动受益，业务侧零改动。

## 5. 键鼠与交互（2in1）

1. **快捷键**：`Ctrl+1~4` 切换四个页签、`Ctrl+N` 新建接口 / 串联链（`pages/Index.ets`）；`Ctrl+S` 保存（`AddPage` / `ChainEditPage`）。
2. **鼠标 hover**：可交互卡片、设置项、图标按钮、滑动操作项统一 `hoverEffect(HoverEffect.Highlight)`（`AppCard`、`AppIconButton`、`AppIconAction`、`AppSwipeAction`、`AppDialog`、各设置卡片等已内置），触控目标尺寸不变。
3. **焦点**：可点击行 / 卡片 `focusable(true)` + `focusOnTouch(true)`，Enter / Space 触发与点击一致的动作；Tab / 方向键走焦与外接键盘 ESC 返回沿用系统默认行为，不拦截输入框方向键。
4. **图表全屏**：柱状图 / 折线图支持全屏查看，进入全屏自动切换横屏、退出恢复原方向（`ChartWidgetViewer`）。

## 6. 官方文档依据

以下结论来自本地官方文档（`devecocli docs`）：最佳实践/平板/平板应用开发、一次开发_多端部署概览、多设备界面开发/布局概述、界面布局响应式变化/响应式布局、媒体查询。

### 6.1 断点定义（响应式布局）

横向断点（窗口宽度）：

| 断点 | 窗口宽度（vp） | 典型设备 |
| --- | --- | --- |
| xs | (0, 320) | 穿戴（折叠并入 SM 处理） |
| sm | [320, 600) | 手机竖屏 |
| md | [600, 840) | 平板竖屏、双折叠展开、手机分屏 |
| lg | [840, 1440) | 平板横屏（MatePad 全屏约 1137×711vp = lg/sm） |
| xl | [1440, +∞) | PC（折叠并入 LG 处理） |

### 6.2 平板特性与交互要点

- 平板支持全屏、分屏、自由多窗、悬浮窗四种窗口模式；自由窗口缩小到 <600vp 时自动退回 SM 布局。
- 跟手半模态：`bindSheet` 设置 `preferType: SheetType.POPUP` 后，窗口宽度 <600vp 显示底部弹窗，其余自动适配为跟手 / 居中弹窗（AppSheet 采用此做法）。
- 键鼠适配：外接键盘默认 ESC 返回上一页；可交互组件适配鼠标 hover（交互归一）、常用快捷键与焦点导航。
- 兼容模式：不声明 tablet 的应用默认以兼容模式上架平板；声明后即原生分发。

### 6.3 部署模型

手机与平板属同一泛类，官方推荐部署模型 A：一套代码工程、一次编译、同一 HAP 在多类设备运行。无需拆分 products 层或多 HAP。

## 7. 测试与验收矩阵

以下矩阵随 1.2.0 验收通过，作为后续回归清单：

| 维度 | 覆盖项 |
| --- | --- |
| 设备/形态 | 手机竖屏（sm 基线回归）；平板竖屏（md/lg）；平板横屏（lg）；平板左右分屏；自由窗口拉大/缩小（断点切换）；悬浮窗；2in1 自由窗口 |
| 断点切换 | 横竖屏旋转、自由窗拖拽跨越 600/840vp 时布局实时刷新、无白屏闪退、页签与路由状态保持 |
| 2in1 布局 | Split 右栏铺满、≥640vp 双列、<640vp 单列；导航栏宽度随窗口收敛（320/360vp）；双列切换不丢焦点 |
| 键鼠 | 卡片/设置项 hover 高亮；Tab 走焦与焦点框；Enter/Space 激活；Ctrl+1~4 / Ctrl+N / Ctrl+S；鼠标滚轮滚动 |
| 页面冒烟 | 四页签、AddPage 保存/发送/提取、结果页与可视化、链编辑与执行、环境变量增删改、备份导入预览、日志导出、扫码导入 |
| 弹窗族 | 全部 AppSheet 在 md/lg 下为 POPUP/居中形态且宽度受限；AppDialog 深浅色与遮罩 |
| 视觉 | 深色模式、大字体（fp 缩放）、侧边页签下的材质表现 |
| 兼容性 | 手机包在平板上从兼容模式切换为原生运行后数据无变化（RDB/Preferences 与设备类型无关） |
| 工程门禁 | codelinter、`devecocli build`、既有单测（占位符/提取/备份逻辑与断点无关，应全绿） |

验收命令：`devecocli build` + 平板模拟器/真机 `devecocli run --skip-build`。

## 8. 边界与后续迭代

- 手写笔能力本期不涉及；确认分屏、自由窗口与 2in1 悬浮窗下布局正确即可。
- 极窄自由窗口（xs，<320vp）并入 SM 处理，长文本 `maxLines` + 省略号兜底。
- 图表全屏与 POPUP 弹窗下的可读性已随 1.2.0 真机验收；如后续图表类型扩展，需同步回归宽屏形态。
- 悬浮页签（`barFloatingStyle`）与沉浸光感材质仅作用于 SM 形态；MD/LG 侧边页签使用常规材质，已验证无异常。
